# GitHub Copilot adapter (design, not implemented)

Status: design only. Build it when a project is actually worked on with Copilot.
Items marked *unverified* must be checked against the Copilot documentation first.

## Plan

| Contract item | Mechanism |
|---|---|
| Expose skills | Copilot discovers project skills in `.github/skills/`, `.claude/skills/`, or `.agents/skills/`. Copying skills into every project is what the harness avoids, so the preferred option is a user-level skills directory if Copilot supports one (*unverified*). Fallback: a script that syncs `skills/` into `.github/skills/eng-*` with a version stamp and a CI check for drift. |
| Session context | `.github/copilot-instructions.md` points to `AGENTS.md` and to `.engineering/.context.md` generated by `bin/eng-context`, as in the Codex adapter. For the Copilot coding agent running in GitHub, the generated file must be committed or produced in the agent's setup steps (*unverified*). |
| `$HARNESS` | In the generated context file. For cloud agents, the harness must be available in the environment (checkout step). |
| Frontmatter | Unknown fields ignored. |

## Project setup (when implemented)

1. `.github/copilot-instructions.md`: one paragraph pointing to `AGENTS.md` and
   the generated context.
2. Decide between user-level skills and synced `.github/skills/` after checking
   what Copilot supports at that time.
