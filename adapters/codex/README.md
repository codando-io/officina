# Codex adapter (design, not implemented)

Status: design only. Build it when a project is actually worked on with Codex.
Items marked *unverified* must be checked against the Codex documentation first.

## Plan

| Contract item | Mechanism |
|---|---|
| Expose skills | Per-skill symlinks `~/.codex/skills/eng-<skill>` → `<harness>/skills/<skill>` (Codex reads `SKILL.md` skills from `~/.codex/skills`). Prefix `eng-` avoids collisions. |
| Session context | Codex has no session hook (*unverified*). A small script runs `bin/eng-context` and writes `.engineering/.context.md` (gitignored); the project `AGENTS.md` tells the agent to read it first. The file is regenerated by the same script, by a git hook, or by the `adopt` skill in check mode. |
| `$HARNESS` | Contained in the generated context file. |
| Frontmatter | Unknown fields ignored by the standard. `disable-model-invocation` has no Codex equivalent (*unverified*); `release` and `adopt` rely on their descriptions ("run only when the user asks"). |

## Project setup (when implemented)

1. `AGENTS.md` gets a first line: "Before working, read `.engineering/.context.md`
   (generated by the engineering harness)."
2. `.gitignore` gets `.engineering/.context.md`.
